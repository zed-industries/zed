# Migration Guide: v1.0.0 to v1.1.0 (Headless Daemon & JSON-RPC Protocol)

## Overview
Zed v1.1.0 introduces native headless daemon support, allowing external agents, automated CI/CD runners, and headless test harnesses to control Zed programmatically via JSON-RPC 2.0 without requiring a GPU or display server.

## Key Changes

### 1. New Command-Line Flags
- `--daemon`: Starts Zed in headless server mode. Bypasses GPU initialization and window management.
- `--daemon-auth-token <TOKEN>`: Specifies the bearer authentication token (can also be supplied via `ZED_DAEMON_TOKEN`).
- `--daemon-listen-addr <ADDR>`: TCP bind address (defaults to `127.0.0.1:9257`).
- `--stdio`: Streams JSON-RPC 2.0 requests over stdin/stdout.

### 2. Upgrading Scripts & Agent Workflows

#### Previous (v1.0.0):
```bash
# Required GUI window or virtual framebuffer (Xvfb)
zed --wait path/to/project
```

#### New (v1.1.0):
```bash
# Run programmatically over standard input/output
echo '{"jsonrpc":"2.0","id":1,"method":"daemon/status","params":{},"auth_token":"secret"}' | zed --daemon --stdio
```

### 3. Public API Crate (`zed_api`)
Direct internal imports from `zed::` are deprecated in favor of the `zed_api` crate:
```rust
use zed_api::{EditorCore, EditorBackend, EditOperation, Range, Position};

let backend = EditorBackend::new();
let buf_id = backend.open(PathBuf::from("main.rs"), Default::default())?;
```
